# Dynamic Island — Implementation Plan

## Concept

A single system-wide overlay ("Dynamic Island") at **top-center** of the active monitor: a dark rounded pill (icon + title, optional subtitle) that slides in only when something happens and auto-hides. It is the reformed successor of the current bottom-center HUD — one overlay system, one window, one API for everything (display switching, Spotify track changes, clipboard copies, emoji copies, and any future extension).

**Window strategy (answering your question):** keep the proven pattern already used by the HUD — a *pre-created, hidden, transparent, always-on-top, skip-taskbar, non-focusable* window that is shown on demand and auto-hidden by a Rust tokio timer. Creating windows on the fly is slower and causes focus flicker; showing/hiding an existing window is instant. Since Asyar is in Beta and we're doing a clean break, we **rename/repurpose the `hud` window into `island`** rather than keeping two overlays.

## Phase 1 — Rust: evolve `hud_window` into `island` window

Files: `src-tauri/src/hud_window/service.rs` (rename module to `island_window`), `src-tauri/src/commands/hud.rs` (rename to `commands/island.rs`), `src-tauri/src/lib.rs`, `tauri.conf.json`, `capabilities/hud.json` → `island.json`, `vite.config.js`, `src-tauri/src/commands/window.rs` (`hide_window` usage).

1. Rename window label `hud` → `island`, route `/hud` → `/island` (`hud/index.html` → `island/index.html`, Vite multi-page entry in `vite.config.js:56`), window size stays compact (~420×88) but repositioned.
2. Replace `position_at_bottom_center` with `position_at_top_center` (top margin ~12px, monitor under cursor — reuse existing monitor resolution logic).
3. New payload type `IslandContent` (derive `specta::Type` so it lands in `bindings.ts`): `{ icon?: string, title: string, subtitle?: string, durationMs?: number }`.
4. Keep the existing show/auto-hide mechanics (`HudState` → `IslandState`, reveal-gen, tokio timer, `emit_to("island", "island:show", ...)`). Cancel-and-replace on rapid successive events (already supported by reveal-gen).
5. Commands: `show_hud` → `show_island`, `get_hud_state` → `get_island_state`; register in `generate_handler!` (lib.rs ~247). Thin wrappers delegating to the service module (architectural invariant).

## Phase 2 — Frontend: island page + host service

1. Rename `src/routes-react/HudPage.tsx` → `IslandPage.tsx`, `hud.css` → `island.css`. Listen to `island:show` event + `getIslandState()` fallback on mount, keep the two-rAF flash-free reveal.
2. Visual design (follow `design-language` skill during implementation): black rounded-full pill, app icon (or extension icon) left, bold white title, dimmed subtitle, subtle scale/opacity spring animation on appear and collapse. Display-only: no click/hover handlers.
3. New host service `src/services/island/islandService.ts` with `showIsland(options)` wrapping the `show_island` command (via `commands.ts` + `invokeSafe`), replacing `feedbackService.showHUD` / `showHUDSpinning`.
4. Migrate existing callers:
   - `src/built-in-features/window-management/index.ts:121` — display switch → `islandService.show({ icon: '🖥', title: 'Next Display' })`.
   - Remove `showHUD`/`showHUDSpinning` from `feedbackService` and the `feedback` registry entry (clean break, no shims).

## Phase 3 — Wire built-in event sources

All go through `islandService.show(...)` — no UI special-casing:

1. **Spotify** (`src/built-in-features/spotify/`): on track change and on next/previous media action, show island with track name + artist (icon: album art if trivially available as image URL, else music glyph).
2. **Clipboard** (`src/services/clipboard/`): on successful copy, brief "Copied" island with a content-type icon.
3. **Emoji extension** (`extensions/emoji/`): on emoji copy, same clipboard path (it already routes through clipboard:write) — covered by #2; verify and only add an explicit call if the emoji copy path bypasses the clipboard service.

## Phase 4 — Extension-facing API (new `island` SDK namespace)

End-to-end per the platform recipe:

1. `asyar-sdk/src/ipc/namespaces.ts`: add `'island'` to `NAMESPACES`.
2. `asyar-sdk/src/services/`: `IIslandService.ts` (`show(options): Promise<void>` — serializable payload only: icon, title, subtitle, durationMs) + `IslandServiceProxy.ts` extending `BaseServiceProxy`; instantiate in `buildFullProxyBag()` (`ExtensionContext.ts`), export from `services/index.ts`; bump SDK version.
3. Host registry: add `island: islandService` in `buildServiceRegistry.ts`; add `'island'` to `INJECTS_EXTENSION_ID` for audit logging/attribution.
4. Permissions: gate `asyar:api:island:show` in `src-tauri/src/permissions.rs` → permission string `island:show`; regenerate the permission catalog (`pnpm gen:all` — never hand-edit generated files).
5. Document `context.island.show({...})` in `docs/reference/sdk/`.

## Risks / notes

- Renaming the window label touches tauri.conf + capabilities + Vite entry; all mechanical, but done in one commit-sized pass to avoid a broken intermediate state.
- The `snap-guides` window is untouched.
- If album art in the pill proves fiddly (remote image fetch in overlay window), ship the text-only version first — the payload already supports an optional icon.
